# 模块 15:AI 时代认知与行为面

> **优先级:🔥 必问**　**覆盖 JD:全员(每个 JD 都强调"正确认识 AI 价值""自驱""学习")**
> 技术面之外,**几乎每场 Agent 岗面试都有这一块**。JD 全都点名了软素质:把 AI 当提效工具而非替代者、自驱爱折腾、跟进前沿、沟通协作。这些问题答得好不好,直接决定 offer 级别。

## 知识地图:行为面考察的 4 个维度

```
① 认知    (你如何看待 AI / 程序员定位 / 技术趋势)
② 实践    (你日常怎么用 AI / 提效工作流)
③ 经验    (讲一个 Agent 项目 / 踩过的坑)
④ 软素质  (自驱 / 学习 / 协作 / 抗压)
```

> 💡 行为面的核心:**有具体例子,不空谈**。每个观点都要能落到"我做过 X,结果是 Y"。

## 第一部分:认知题(你怎么看 AI)

### Q15.1【必问】有了 AI 以后,程序员的定位发生了什么变化?你怎么看?

**考察点:** 这是最高频的开放题,JD1 明确"正确认识 AI 价值"。考察是否理性、有深度。

**参考答案要点(有观点 + 不极端):**
- **价值上移**:程序员的核心价值从"写代码"转向:
  - **定义问题**:把模糊业务需求变成清晰的技术目标(这是 AI 最难替代的);
  - **架构设计**:技术选型、系统边界、trade-off 判断;
  - **质量把关**:Review AI 输出、保证可靠性与安全性;
  - **业务驱动**:理解业务、用技术创造价值。
- **"写代码"本身的贬值**:
  - 实现层面的编码越来越自动化(AI 补全/Agent);
  - 纯"翻译型"工作(把明确需求变成 CRUD)最易被替代;
  - 代码量 ≠ 价值。
- **正确的认知**(对齐 JD 理念):
  - **AI 是生产力放大器,不是替代者**(JD1 原话);
  - 不是"AI 替代程序员",而是"会用 AI 的程序员替代不会用的";
  - 程序员从"执行者"变成"指挥者/架构师/审核者"。
- **不变的东西**:工程素养(抽象、复用、测试、运维)、业务理解、系统性思维 —— 这些 AI 时代更值钱。
- **自我定位**(结合个人讲):我把自己定位为"驾驭 AI 解决问题的工程师",重心在定义问题、设计、把关,AI 帮我把执行效率放大 10 倍。

**追问方向:** 那初级程序员怎么办?(学习用 AI 放大自己、往上走做判断,而非和 AI 比编码速度)

---

### Q15.2【必问】你会不会被 AI 替代?哪些能力是 AI 替代不了的?

**考察点:** 自我认知 + 对 AI 能力边界的理解。

**参考答案要点:**
- **短期不会被替代**,但要持续进化。
- **AI 替代不了的**:
  - **责任与决策**:出问题谁负责、关键决策谁拍板;
  - **复杂问题定义**:把真实世界的模糊痛点变成清晰可解的问题;
  - **跨领域综合判断**:业务 + 技术 + 人 + 商业的权衡;
  - **人际协作**:沟通、说服、领导、共情;
  - **创新与从 0 到 1**:突破既有范式的创造;
  - **真实环境适配**:线下、物理、组织政治等 AI 不接触的领域。
- **容易被替代的**:明确、重复、模式内的编码工作。
- **结论**:与其担心被替代,不如**把 AI 变成自己的杠杆**,做 AI 做不了的事,让 AI 做 AI 能做的事。

---

### Q15.3【中】你最近在关注 AI 的什么前沿方向?

**考察点:** 是否真在跟进前沿(每个 JD 都强调"跟进前沿")。

**参考答案要点:**
- **诚实 + 具体**:说 1~2 个真了解的方向,展开讲认知,而非罗列名词。
- **可选方向(举几个有深度的)**:
  - **Agent 可靠性 / 长任务**:如何让 Agent 稳定完成复杂任务(SWE-bench 进展、自我验证);
  - **推理模型(o1/R1 类)**:CoT 内化、test-time compute;
  - **模型成本下降**:小模型能力提升 + 推理优化,让 Agent 大规模落地经济可行;
  - **多模态 Agent**:视觉 + 操作(操作 UI、看图改代码);
  - **AI 编程范式**:SDD / Agentic Coding / 自主 Agent 的成熟度;
  - **对齐与安全**:Agent 安全、Prompt 注入防御。
- **加分**:能讲清"这个方向对业务/自己的影响",而非纯学术。
- **避免**:只甩名词、说不出所以然。

## 第二部分:实践题(你怎么用 AI)

### Q15.4【必问·高频】你日常怎么用 AI 提效?讲具体场景。

**考察点:** 是否真重度用户(每个 JD 都要求)。**这是必问题,要准备 3~5 个真实场景。**

**参考答案要点(准备多个场景,挑最亮眼的讲):**
- **场景库(各准备一个)**:

| 场景 | 怎么用 | 量化效果 |
|---|---|---|
| **写新 feature** | SDD:先写 spec → AI 实现 → 我 review + 测试 | 提速 3~5 倍 |
| **重构老代码** | 让 AI 先理解 → 分步重构 → 跑测试验证 | 原来不敢动的代码敢动了 |
| **写测试** | AI 生成单测 + 边界 case,我补充关键路径 | 覆盖率从 X 到 Y |
| **学习新技术** | 让 AI 当导师:解释概念 → 出题 → 帮我 debug | 上手速度翻倍 |
| **Debug** | 贴报错 + 上下文,AI 辅助定位 | 排查时间减半 |
| **文档 / 周报** | AI 起草,我改 | 省时间专注核心 |
| **代码评审** | AI 先扫一轮,我 focus 关键 | 漏检率下降 |
| **调研选型** | AI 搜集对比,我决策 | 决策更快 |

- **答题结构**:场景 → 具体做法 → 效果 → 我的判断(哪些交 AI、哪些自己做)。
- **加分**:讲一个"用 AI 做了以前做不到的事"(能力扩展),而非仅"做得更快"。

---

### Q15.5【中】你用 AI 遇到过什么坑?怎么解决的?

**考察点:** 实战经验的真实性(没踩坑 = 没深度用)。

**参考答案要点:**
准备 1~2 个真实坑:
- **幻觉 API / 过时写法**:AI 生成不存在的函数 → 学会查文档验证 + 跑测试;
- **大任务跑偏**:让 AI 一次改太多 → 改成小步快跑 + Plan/Todo;
- **上下文不足产出差**:AI 不懂项目约定 → 加规则文件 + 精准 @ 引用;
- **过度依赖**:不 review 直接用导致 bug → 建立质量门禁;
- **成本失控**:复杂任务烧 token → 学会拆分、用对模型;
- **安全风险**:AI 生成硬编码密钥 → Review 重点查安全。
- **体现成长**:每个坑要讲"后来我怎么避免",展示学习能力。

---

### Q15.6【中高】如果让你给团队推广 AI 工具 / 工作流,你会怎么做?

**考察点:** 影响力 + 推动力(JD3 强调"放大个人技术影响力")。

**参考答案要点:**
- **不只自己用,还能带动团队**:
  - **试点**:自己先跑通一个提效工作流,拿到量化结果;
  - **示范**:用真实案例(对比 before/after)说服,而非空谈理念;
  - **降门槛**:沉淀 Skills / 规则文件 / 模板,让同事易上手;
  - **培训**:做分享、写文档、答疑;
  - **制度化**:把 AI 工具纳入流程(如 PR 模板、CI 集成);
  - **度量**:跟踪团队提效指标,持续迭代。
- **关键认知**:推广不是"逼大家用",是"让大家看到价值、降低门槛、形成习惯"。

## 第三部分:项目经验深挖(讲一个 Agent 项目)

### Q15.7【必问·高频】讲一个你做过的 Agent / AI 项目。

**考察点:** 真实经验 + 表达能力。**这是技术面的核心大题,要按 STAR 准备。**

**参考答案要点(用 STAR 框架):**
- **S(Situation)背景**:业务场景、为什么要做、痛点;
- **T(Task)任务**:你的角色、目标、约束;
- **A(Action)行动**(重点,体现技术深度):
  - 架构设计(为什么这么设计);
  - 关键技术选型(为什么选 X 不选 Y);
  - 难点 & 解决(踩了什么坑、怎么解决);
  - 你的具体贡献(区分团队 vs 个人);
- **R(Result)结果**(量化!):
  - 业务指标(准确率、效率提升、成本下降);
  - 技术指标(延迟、QPS、覆盖率);
  - 影响范围(用户数、推广度)。

- **常见追问 & 要准备**:
  - "为什么用这个框架/模型?"
  - "最难的部分是什么?怎么解决的?"
  - "如果重做,你会怎么改进?"
  - "这个项目的规模 / QPS / 数据量?"
  - "你和别人怎么分工的?"

- **避坑**:
  - 别只讲"我用了 LangChain" —— 讲**为什么、遇到什么问题、怎么决策**;
  - 别夸大(深问会穿帮);
  - 别只讲技术不讲业务价值;
  - 量化结果(没有数字的项目经验很苍白)。

---

### Q15.8【高】你做的 Agent 项目,如果让你重新设计,你会怎么改进?

**考察点:** 反思能力 + 持续进化思维。

**参考答案要点:**
体现"做过 + 想清楚 + 在进步":
- **架构层面**:哪些设计当时不合理(如耦合、扩展性);
- **技术选型**:有没有更好的方案(新框架/新模型);
- **工程化**:当时缺了什么(评测、监控、可观测);
- **效果**:哪些可以做得更好(准确率、成本);
- **方法论**:如果用现在的认知(SDD/Skills)会怎么做。
- **关键**:展示你不固步自封,有复盘和迭代意识。

## 第四部分:软素质题

### Q15.9【中】遇到完全不懂的新技术,你怎么快速上手?

**考察点:** 学习能力(每个 JD 都强调"学习能力强")。

**参考答案要点:**
- **方法论**:
  - **先建框架认知**:用 AI/搜索快速了解"这是什么、解决什么、核心概念";
  - **动手跑通最小例子**:不求全懂,先跑起来;
  - **以问题驱动深入**:带着真实问题学,边做边查;
  - **对比已知**:和熟悉的技术对比,加速理解;
  - **输出倒逼输入**:写笔记 / 讲给别人听,检验理解;
  - **看源码 / 官方文档**:深入时回到一手资料。
- **AI 的作用**:把 AI 当导师(解释、答疑、出题、debug),大幅加速学习。

---

### Q15.10【中】你怎么看待加班 / 压力 / 未知技术挑战?

**考察点:** 抗压 / 态度(JD2 强调"抗压能力")。

**参考答案要点:**
- **理性态度**:
  - 不排斥为有价值的事投入,但反对低效内卷;
  - 压力来自"未知"时,拆解问题、小步推进是解药;
  - 面对未知技术挑战,**问题定义能力**和**借助 AI/社区快速学习**是关键;
  - 关注结果,也注重过程沉淀(可复用的 Skills/经验)。
- **避免**:空喊"我抗压""我热爱加班";讲具体怎么应对过压力。

---

### Q15.11【必问】你为什么想做 Agent 方向?为什么选我们公司/团队?

**考察点:** 动机 + 匹配度。

**参考答案要点:**
- **为什么做 Agent**:
  - 看好方向:Agent 是 LLM 落地的核心形态,正在重塑软件研发与业务;
  - 匹配能力:自己有工程 + AI 兴趣,适合这个交叉领域;
  - 价值感:能用 AI 放大生产力,做从 0 到 1 的事。
- **为什么选这个团队**(结合具体 JD):
  - 字节底座(JD1):平台化、SDD/Harness 实践,能做行业级底座;
  - 数据中台(JD2):算法深水区,能做模型 + 工程双修;
  - 美团 M 端(JD3):业务落地、AI Native 转型,成果可见;
  - Coding Agent(JD4):用 AI 改造研发本身,方向前沿。
- **真诚 + 具体**:别泛泛而谈,要体现你了解这个团队做什么。

## 第五部分:反问环节(你的提问)

### Q15.12【建议准备】面试最后"你有什么想问的?"

**考察点:** 你的思考深度与兴趣。

**建议准备的问题(挑 2~3 个)**:
- **业务/技术**:
  - "团队目前 Agent 落地最大的挑战是什么?"(真实痛点)
  - "团队的 Agent 架构是怎样的?用什么框架?"
  - "怎么评估 Agent 效果?有评测体系吗?"
  - "团队内部怎么用 AI 提效?有没有沉淀 Skills/工作流?"
- **成长**:
  - "新人进来主要做什么?成长路径?"
  - "团队怎么看 AI Native 转型?"
- **避免**:问百度能查到的、只关心钱/加班(留到 HR 面)。
- **价值**:好问题 = 展示你懂行 + 真感兴趣。
