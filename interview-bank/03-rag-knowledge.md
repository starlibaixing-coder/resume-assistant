# 模块 03：RAG & 知识库

> **优先级：🔥 必问**　**覆盖 JD：JD1/2/3（RAG、知识库治理均为明确要求）**
> RAG 是大模型落地最主流的范式，几乎每场 Agent 面试都会深挖。重点考察检索效果优化、幻觉治理、知识库治理三大方向。

## 知识地图：RAG 完整链路

```
文档解析 → 切块(chunking) → 向量化(embedding) → 入库
    → 检索(retrieval) → 重排(rerank) → 拼 prompt → 生成 → 引用校验
```

| 环节 | 关键技术 |
|---|---|
| 文档解析 | PDF/表格/图片处理、多模态、结构化抽取 |
| 切块 | 固定大小+overlap、按语义边界、Parent-Child、Layout-aware |
| 向量化 | BGE / M3E / OpenAI / Qwen embedding |
| 向量库 | FAISS / Milvus / Qdrant / pgvector |
| 检索 | 纯向量、Hybrid（向量+BM25）、Multi-Query、HyDE |
| 重排 | Cross-encoder rerank（BGE-reranker 等） |
| 生成 | 上下文压缩、引用强制、faithfulness 校验 |
| 进阶 | GraphRAG、自适应检索、Self-RAG |

## 题目

### Q03.1【高·必问】RAG 检索效果差，你怎么优化？

**考察点：** 是否有系统性的 RAG 优化方法论（不是只会一句"换个 embedding"）。

**参考答案要点：**
按链路逐段排查，**召回端**和**排序端**两端讲：
- **召回端（没检索到）**：
  - 切块策略：块太大丢精度、太小丢上下文 → 调 chunk size + overlap；按语义边界切；Parent-Child（检索小块，返回大块保上下文）。
  - Query 改写：Multi-Query（生成多个子查询）、HyDE（假设性文档）、同义词扩展。
  - 混合检索：Hybrid（向量 + BM25），向量管语义、BM25 管关键词。
  - 提高 top-k，加 metadata 过滤（时间 / 来源 / 权限）。
  - 换更好的 embedding 模型（中文场景 BGE-M3 等）。
- **排序端（检索到了但排后面）**：
  - 加 rerank（cross-encoder 精排），这是性价比最高的一招；
  - 调整召回数与精排数的比例。
- **生成端（检索到了但没用上）**：
  - 上下文顺序（关键信息放前面，避免 "lost in the middle"）；
  - Prompt 引导（"仅依据以下内容回答"）。
- **方法论**：先建评测集定位是召回问题还是排序问题，再对症下药。

**追问方向：** 怎么判断是召回不足还是排序不准？（对照标注的 relevant docs，看 recall@k 和 MRR）

### Q03.2【高·必问】大模型幻觉在 RAG 里怎么治？

**考察点：** 幻觉治理的工程手段。

**参考答案要点：**
- **检索层**：确保检索质量（检索不到就只能瞎编）。
- **Prompt 层**：
  - 强约束："仅依据以下资料回答，资料中没有的就说不知道"；
  - 要求引用来源（每个论断标注出处 chunk）。
- **后校验**：
  - faithfulness 校验（用 LLM-as-Judge 判断答案是否被检索内容支持）；
  - 实体校验（答案中的实体是否出现在检索内容）。
- **进阶**：Self-RAG（模型自己判断是否需要检索、是否可信）。
- **兜底**：低置信度时拒绝回答或转人工。

### Q03.3【中高】知识库怎么治理？JD3 说的「知识库自进化」你理解是什么？

**考察点：** 知识库的工程治理 + 持续演进思维（直接对应 JD3 岗位亮点）。

**参考答案要点：**
- **治理**：
  - 版本管理（知识有版本，可回滚）；
  - 失效检测（旧知识标记过期 / 自动更新）；
  - 去重、质量控制（低质 chunk 清理）；
  - 权限与可见性（不同用户不同知识范围）；
  - 溯源（每条知识来自哪个文档、何时入库）。
- **自进化（关键）**：
  - **自动入库**：用户提问但知识库没有 → 触发知识补充流程；
  - **反馈驱动**：bad case 反向补全（检索失败 → 补充相关知识）；
  - **质量评估**：定期评测知识有效性，淘汰低使用率 / 低准确率知识；
  - 形成与数据飞轮的闭环（见 Q10.9）。

### Q03.4【中】文档里有大量表格 / 图片，RAG 怎么处理？

**考察点：** 多模态 / 非结构化数据处理。

**参考答案要点：**
- **表格**：
  - 结构化抽取（转 markdown 表格 / JSON），保留行列关系；
  - 对表格做摘要 + 明细双层索引（摘要用于召回，明细用于回答）；
  - 复杂表格可用 Text-to-SQL（先检索到表，再用 NL2SQL 查询）。
- **图片**：
  - 多模态 embedding（CLIP 等）；
  - 或用 VLM（视觉大模型）转文字描述后再入库；
  - 图表数据可 OCR + 结构化。
- **版式**：用 Layout-aware 切块（保留标题、段落、页眉页脚结构）。

### Q03.5【高】百万级文档，向量库怎么选？检索性能怎么保证？

**考察点：** 向量库的工程选型 + ANN 原理（结合模块 11）。

**参考答案要点：**
- **选型对比**：
  - FAISS：库，适合单机、研究；不擅长实时增删。
  - Milvus：分布式，适合大规模生产；重。
  - Qdrant：Rust 实现，性能好，过滤能力强。
  - pgvector：PostgreSQL 扩展，与业务库一体，适合中小规模 + 事务需求。
- **性能**：
  - 用 ANN（HNSW / IVF + PQ）而非暴力检索；
  - 分区 / 分片（按业务维度分区，缩小检索范围）；
  - metadata 预过滤（先过滤再检索，降候选集）。

**追问方向：** HNSW 和 IVF 的区别？（图索引 vs 聚类索引，详见模块 11）

### Q03.6【中】什么是 Hybrid Retrieval？为什么不能只用向量检索？

**考察点：** 混合检索的认知。

**参考答案要点：**
- **纯向量的局限**：
  - 对精确关键词（人名、编号、专有名词）不敏感；
  - 对短 query 效果差（语义信息少）。
- **Hybrid**：向量（语义匹配）+ BM25（关键词匹配）→ 加权融合（RRF 或线性加权）→ 兼顾语义和关键词。
- **场景**：法律（条款编号）、医疗（药名）、企业内部（系统名）等强关键词场景必备。

### Q03.7【高·进阶】什么是 GraphRAG？和传统 RAG 比有什么优势？

**考察点：** 前沿技术的跟踪（JD1/2 要求跟进前沿）。

**参考答案要点：**
- **传统 RAG 的局限**：基于局部 chunk 检索，难以回答全局性 / 跨文档问题（如"总结整个领域的核心趋势"）。
- **GraphRAG**：
  - 先从文档抽取实体 + 关系，构建知识图谱；
  - 检索时不仅查向量，还沿图谱关系游走，获取全局关联信息；
  - 适合多跳推理、全局总结类问题。
- **代价**：构建图谱成本高（大量 LLM 调用）、维护复杂；适合知识关系密集的领域。
