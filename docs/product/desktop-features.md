# 桌面端功能文档(CommitCareer)

- **性质**:桌面端「应该具备什么」的应然全景清单——产品视角,不描述实现状态;是 PRD(`desktop-prd.md`)的唯一功能输入。
- **推导来源**:README、`specs/2026-08-13-quiz-app-agent-design.md`(ADR 全集)、`specs/2026-09-02-terminology.md`、`specs/2026-08-31-brand-naming.md`、各施工计划(2026-08-19 / 08-26 / 08-27 / 08-28)中经用户确认的功能决策。
- **术语基线**:与 `desktop-prd.md`、原型共用同一基线——UI 层术语一词一义,以 `specs/2026-09-02-terminology.md` 为准;本文档概念名直接沿用其 UI 术语(不引入工程同义词),固定按钮短语不增删一字(添加题目 / AI 生成题目 / 按 JD 生成题目 / 开始复习 N 题 / 开始学习 N 题 / 再过一遍)。
- **优先级**:P0 = 没有就不成立;P1 = 核心体验完整;P2 = 增强;**规划** = 路线图后续阶段,本期不做。

---

## 0. 产品定位

**一个本地优先、自用的求职训练工作台。** 每天的训练(SM-2 间隔重复)是主体;AI 出题经人工把关扩充弹药;求职中枢(JD 与简历)提供定向输入。数据全部留在本机,零上传。

四大价值块:**训练**(每天学什么、怎么学)/ **题库资产**(官方只读 + 我的可经营)/ **出题管线**(手动 / AI / 按 JD,产物必经把关)/ **求职中枢**(JD 与简历)。
