## 1. 产品概述

### 1.1 定位

一个本地优先、自用的桌面刷题应用:每天的学习(SM-2 间隔重复)是主体;AI 出题经人工把关后进题库;JD 与简历用于按岗位定向出题。数据全部留在本机,不上传。

### 1.2 目标用户与场景

前端工程师、或想转 AI Agent 方向的工程师,求职备考期每天使用;键盘熟练;重视数据私有。

三个核心场景:

| 场景 | 用户行为 | 产品职责 |
|---|---|---|
| 每日学习 | 打开应用 → 完成今天的复习与学习 → 看小结离开 | 30 秒内开始学习;评分决定后续复习安排,无需用户管理进度 |
| 出题扩库 | 学到薄弱点 / 看到目标 JD → 出一批题 | 手动、AI、按 JD 三种来源;AI 产物必经审核,库保持干净 |
| 求职定向 | 录入目标 JD 与简历 → 按 JD 出题 → 结合简历出深挖题 | JD 与简历是被出题引用的资产,各自可独立维护 |

### 1.3 产品目标

1. **每日循环成立**:用户每天打开即知道「今天要学什么」,一次会话完整走完(看题 → 想 → 评分 → 小结)。
2. **库永远可信**:进入学习队列的每一道题都经过了把关(人写的直接进,AI 生成的必经审核)。
3. **零心智负担的数据安全**:用户不需要理解存储细节,但随时能看到「数据在本机」。

### 1.4 术语与记法

按功能文档「术语与规范约定」执行,要点:状态五词 待学习 / 待复习 / 已排期 / 已掌握 / 待审核(已排期 = 已学、下次复习日尚在未来的题,ADR-0003);评分三档 不会 / 模糊 / 掌握;把关动作 通过 / 拒绝;调度序列 学习队列;界面动词用「学习」(叙述可用「刷题」),出题动词用「生成」;固定短语一字不改(见功能文档);量词「N 道题」,标签裸数字。本文档模块编号 M1–M10,条目引用功能编号(A1–H4)。

### 1.5 产品原则

1. **打开即学习**:首屏是今日计划,不是仪表盘或内容推荐。
2. **学习是连续体**:一轮会话内零打断——评分后自动推进,不弹确认、不跳页面。
3. **管理即就地**:浏览、编辑、审核都在同一工作面完成,不弹编辑窗、不放二级页面。
4. **键盘是一等公民**:所有高频动作有快捷键;任何可编辑区域(输入框、文本域、代码编辑器)聚焦时不劫持按键。
5. **不可逆必确认,可逆不打断**:删除/拒绝走确认弹窗;其余操作即时生效可撤销(编辑可改回)。
6. **数据本机可见**:状态栏常驻「本地优先 · 数据不上传」。

## 2. 产品结构

### 2.1 功能结构(模块树)

```
CommitCareer 桌面端
├─ M1 全局框架与导航(侧栏/状态栏/⌘K/键盘/守卫与确认/外观/品牌)   ← F1–F7
├─ M2 今天(学习计划/复习预测/累计与连续/学习记录)               ← B1–B4
├─ M3 学习(会话/评分/重排/小结/专注/草稿纸/问 AI/笔记/追问)      ← A1–A10
├─ M4 题库(双分类/浏览筛选排序/详情/编辑删除/官方保护/直搜落点)   ← C1–C6
├─ M5 添加题目(手动写题/AI 生成/按 JD 生成/来源标注)          ← D1–D3、D5
├─ M6 审核(待审核列表与详情/通过/拒绝)                          ← D4
├─ M7 JD 管理(多 JD/统计/深链出题)                              ← E1、E2、E4
├─ M8 简历(编辑/字数/只存本机)                                  ← E3
├─ M9 设置(AI 服务/学习偏好/外观/题库同步/备份)                 ← G2–G4、C1、G3
└─ M10 数据与安全(本地存储/密钥/同步与下架清理)                  ← G1、C1
```

### 2.2 界面结构

窗口分三层:**侧栏(导航)+ 内容区(各界面自定义布局)+ 状态栏(常量信息)**。

```
┌─────────────┬─────────────────────────────────────────────┐
│ 今天      ⌘1 │                                             │
│ 学习      ⌘2 │                                             │
│ 题库      ⌘3 │           内容区(按界面自定义)              │
│ 待审核(N) ⌘4 │                                             │
│ JD 管理   ⌘5 │                                             │
│ 简历管理  ⌘6 │                                             │
│ ─────────── │                                             │
│ 添加题目  ⌘7 │                                             │
│ 设置      ⌘8 │                                             │
├─────────────┴─────────────────────────────────────────────┤
│ 我的 N · 待学习 N · 待复习 N · 待审核 N │ 本地优先 · 数据不上传 │
└─────────────────────────────────────────────────────────────┘
```

- 八个界面 = 侧栏八项平铺不分组(§7-D23),顺序 = 使用频率 × 工作流(学习类在前,求职类居中,工具项垫底);待审核带计数徽标。
- 侧栏不出现品牌名;窗口标题随界面切换为 `{界面名} · CommitCareer`。
- 布局范式(产品决策,详见 §7-D1):
  - **流程型界面**(今天、学习):单列,内容居中,按步骤推进;
  - **管理型界面**(题库、审核、JD 管理):左右双栏 = 列表 + 详情,操作在详情内就地完成;
  - **编辑型界面**(简历、设置):单栏表单/编辑器。

### 2.3 核心流程

**每日学习流**
```
打开 → 今天:看到 待复习 N / 待学习 N
  → [开始复习 N 题] 或 [开始学习 N 题]
  → 学习:题干 → 想清楚 → [我想好了,看答案] → 答案要点(+追问)
  → 评分(不会1/模糊2/掌握3) → 自动下一题 …… → 小结
  → 回到今天(计数已更新)/ 再过一遍
```

**添加题目与把关流**
```
添加题目(手动 / AI / 按 JD)
  ├─ 手动写题 ──────────────→ 我的题库(直接可用)
  └─ AI / 按 JD 生成 → 待审核 → [通过,进我的题库] → 我的题库 + 学习队列
                                 └→ [拒绝](确认) → 永久删除
```

**求职定向流**
```
JD 管理:录入 JD → [按 JD 生成题目] → 添加题目界面(该 JD 已预选)
  → (可选)结合简历生成深挖题 → 待审核 → 通过 → 我的题库 → 待学习
```

### 2.4 全局交互规范

#### 2.4.1 导航与快捷键

| 键 | 语境 | 行为 |
|---|---|---|
| ⌘K | 任意位置(含输入框) | 打开 ⌘K 命令面板 |
| ⌘1–⌘8 | 输入框外 | 切换八个界面(顺序同侧栏) |
| ␣ / Enter | 学习·答案未揭示 | 揭示答案 |
| 1 / 2 / 3 | 学习·答案已揭示 | 不会 / 模糊 / 掌握 |
| F | 学习 | 进入/退出专注模式 |
| ⌘S | 简历编辑 | 保存 |
| ⌘↩ | 审核详情 | 通过 |
| ⌫ | 审核详情 | 打开拒绝确认 |
| ⌘, | 任意位置 | 打开设置(平台惯例,与 ⌘8 等效,§7-D19) |
| ↑ / ↓ | 题库、审核、JD 列表 | 移动选中行 |
| Esc | 确认/守卫弹窗(=取消)> ⌘K > 专注模式 | 逐层退出 |

**按键豁免规则**:任何可编辑区域——输入框、文本域、**代码编辑器等富编辑组件**——聚焦时,除 ⌘K 外的全部快捷键让位给文字输入(例如在代码草稿纸里敲空格、数字、F 必须正常输入字符,不得触发揭示/评分/专注);可编辑区域内的 Esc 优先交给编辑组件自身(如关闭补全浮层),不冒泡执行界面级退出(§7-D14)。

#### 2.4.2 ⌘K 命令面板(F1、C7)

- 结构:输入框 + 分组结果列表。三组:**动作**(开始复习 N 题 / 开始学习 N 题 / 添加题目 / 再过一遍)、**前往**(八个界面)、**题目**(全库模糊搜索题干/考察点/题号/模块)。
- 行为:输入即筛;↑/↓ 选择(鼠标悬停同步),Enter 执行选中项,Esc 关闭;动作组与今天页按钮**同名同义**;动作组中计数为 0 的项不出现;「开始复习 N 题」的 N = 到期全量,「开始学习 N 题」的 N = min(待学习, 题量上限)(ADR-0001);题目组回车 = 跳到题库该题所属分类并选中该行;结果按 动作 > 前往 > 题目 固定分组排序,题目按题号升序。

#### 2.4.3 通用模式

| 模式 | 规则 |
|---|---|
| **不可逆确认** | 删除题目、删除 JD、拒绝题目、导入备份覆盖前,弹确认框:标题为问句 + 正文写明不可恢复及连带影响 + 危险色确认按钮 + 取消;**Esc = 取消,初始焦点落在取消按钮** |
| **未保存守卫** | 表单/编辑器有未保存修改时离开(切界面/切列表项):弹「有未保存的修改」,选择 继续编辑 / 放弃修改并离开(放弃 = 内容恢复为已保存版本) |
| **空态** | 每个列表与面板必须有空态:一句说明 + 一个下一步动作按钮(如「去添加题目」「清除筛选」);计数为 0 的内容不出现,不留「0」占位 |
| **即时反馈** | 操作成功用轻量 toast(1.5–2s 自动消失);**学习会话内的逐题评分反馈在当前题卡就地展示,不用全局 toast**(§7-D26);失败用界面内错误提示(常驻直到修复或关闭)并提供下一步动作(如「重试」「去设置」),不静默失败 |
| **进行中状态** | 异步操作(生成、同步)按钮内联加载指示并禁用重复触发;可取消的操作提供取消 |

#### 2.4.4 外观与主题(F6)

浅色纸面 / 夜读暖黑两套,设置中切换,即时生效,记忆选择。

### M1 全局框架与导航

**定位**:应用的骨架——导航、全局反馈、安全网(守卫与确认)。

**能力清单**

| 能力 | 说明 | 功能 | 优先级 |
|---|---|---|---|
| 侧栏导航 | 八界面平铺不分组 + 待审核计数徽标 | F2 | P0 |
| 状态栏 | 全局计数(我的 N · 待学习 N · 待复习 N · 待审核 N)+「本地优先 · 数据不上传」;计数随评分、审核、出题实时联动(§7-D25:不显示静态的官方总数) | F5 | P0 |
| ⌘K 命令面板 | 见 §2.4.2 | F1、C7 | P0 |
| 全局键盘体系 | 见 §2.4.1(含 ⌘, 进设置与可编辑区域豁免) | F2 | P0 |
| 未保存守卫 | 见 §2.4.3 | F3 | P0 |
| 不可逆确认 | 见 §2.4.3 | F4 | P0 |
| 外观切换 | 浅色/夜读 | F6 | P1 |
| 品牌呈现 | 窗口标题 `{界面名} · CommitCareer`;侧栏无品牌名 | F7 | P1 |

**交互详述**

1. 切换界面:点击侧栏项 / ⌘数字 / ⌘K「前往」;当前界面高亮。离开有未保存修改的编辑型界面先触发守卫。
2. 计数徽标:待审核徽标 = 待审核数;今天徽标 = 待复习 + 待学习 + 待审核之和(为 0 时不显示)。
3. 状态栏计数在以下时刻自动刷新:评分落库、通过/拒绝、生成提交、手动保存、同步完成。
4. Esc 层级:确认/守卫弹窗(等效取消)→ ⌘K → 专注模式,逐层退出;无层级可退时 Esc 不做事;可编辑区域内的 Esc 优先交给编辑组件(如关闭补全),不冒泡。
5. **多窗口规则**(§7-D21):问 AI 为独立子窗口;⌘W 只关闭当前焦点所在窗口(关问 AI 窗口不影响主窗口);主窗口退出(应用退出)时一并关闭问 AI 子窗口;专注模式的系统全屏联动在进入/退出时完整还原窗口原状态,用户在系统层手动退出全屏时专注态同步退出。

**验收**:⌘1–⌘8 与 ⌘, 全部可达且顺序与侧栏一致;徽标随操作实时变化;可编辑区域聚焦时按 1/2/3/空格/F 不触发学习快捷键;状态栏计数与库内状态一致。

### M2 今天

**定位**:应用的默认首页与每日入口——回答「现在该学什么」。

**能力清单**

| 能力 | 说明 | 功能 | 优先级 |
|---|---|---|---|
| 今日学习计划 | 待复习 / 待学习 / 待审核三行,各带主按钮(开始复习 N 题 / 开始学习 N 题 / 去审核) | B1 | P0 |
| 复习预测 | 未来 7 天每天到期题数,柱状展示,数量最多的一天高亮 | B2 | P1 |
| 累计与连续 | 已学题目 / 已掌握 / 连续学习 N 天 | B3 | P1 |
| 最近学习记录 | 按日:学习了 N 道题,掌握 N 道 + 完成时间 | B4 | P2 |

**布局**(流程型,左主右辅)

```
┌ 今天 ──────────────────────────────── [添加题目] ┐
│ ┌ 学习计划(主卡) ─────────────┐ ┌ 复习预测(7 天柱状) ┐ │
│ │ 3 待复习  [开始复习 3 题]    │ ├ 累计 ──────────────┤ │
│ │ 4 待学习  [开始学习 4 题]    │ │ 已学 已掌握 连续天数 │ │
│ │ 2 待审核  [去审核]          │ └────────────────────┘ │
│ └─────────────────────────────┘ ┌ 最近学习记录 ───────┐ │
│                                 │ 昨天 17 道 · 14:20  │ │
│                                 └────────────────────┘ │
└──────────────────────────────────────────────────────┘
```

**交互详述**

1. **计划行**:每行 = 数字 + 名称 + 一句说明 + 主按钮。数字含义:待复习 = 今天到期的已学题;待学习 = 尚未开始学的题;待审核 = AI 生成待把关的题。
2. **开始复习 N 题 / 开始学习 N 题**:进入对应学习会话(队列规则见 M3)。**复习不设上限**——N = 真实到期数,逾期债当日清零(ADR-0001);**开始学习 N 题**的 N = min(待学习数, 每次学习题量),被截断时行内注明「共 M 题,本轮先取 N 题」,状态行数字仍显示真实总数。两个按钮直接开题,无确认。
3. **去审核**:跳转审核界面。
4. **零值行不出现**:某类计数为 0 时整行隐藏;三类全为 0 时,主卡显示完成态——「今日队列已清空 / 该复习的、该学的都完成了,明天见」+ 次要按钮「再过一遍」(队列 = 全部题,含已掌握;结构与上限语义见 §7-D36)。
5. **计数联动**:学习评分、审核通过/拒绝后,回到今天时数字立即反映(状态栏同步)。
6. **复习预测**:7 根柱,横轴为 今天/明天/周几;hover 显示当日到期数;仅展示,不可点击。
7. **连续学习天数规则**(产品决策,§7-D4):当天完成至少 1 次评分记为「已学习」;中断一天即从 1 重新计数。
8. **添加题目**(右上):跳转添加题目界面。

**状态与边界**:首次使用(官方题库就绪、无任何进度)= 只有「待学习 N(全库)」一行 + 开始按钮;同步刚拉到新分类时,待学习数即时包含新增的题。

**验收**:三类计数与库内状态一致;零值行隐藏、全清态正确;「开始复习 N 题」开的队列恰好是 N 道到期题;评分后返回,待复习计数减少。

### M3 学习

**定位**:产品的核心体验——一轮完整、低打断的记忆学习。

**能力清单**

| 能力 | 说明 | 功能 | 优先级 |
|---|---|---|---|
| 学习会话 | 队列构造、进度展示、强制思考(先想后看)、评分后自动推进 | A2 | P0 |
| SM-2 调度 | 待复习优先、待学习补位;三档评分;评分决定下次复习时间 | A1 | P0 |
| 「不会」重排 | 评「不会」的题复制一份排到本轮末尾重练一次(带重练标识);原题按评分排期 | A3 | P0 |
| 会话小结 | 统计 + 逐题评分与下次复习时间;回到今天 / 再过一遍 | A4 | P0 |
| 单题直练 | 从题库详情对一道题直接开会话 | A5 | P1 |
| 专注模式 | 隐去全部壳、题面放大;Esc 退出;桌面环境下联动系统全屏 | A6 | P1 |
| 代码草稿纸 | 题卡内可折叠代码区,按题保存;JS 可运行(沙箱、超时终止、异步输出可见) | A7 | P1 |
| 按题笔记 | 学习中可写本题笔记 | A8 | P1 |
| 问 AI | 独立子窗口打开 AI 聊天网页(如 chat.qwen.ai);已开则聚焦;不授予该窗口任何应用权限 | A9 | P1 |
| 追问展示 | 揭示答案后展示本题追问(面试官可能接着问) | A10 | P1 |

**布局**(流程型,题卡居中,阅读宽度受限)

```

{当前题序号} / {总数} ━━━━━━━━━━━━━━━━━━━ 进度条

│                                          │
│  ── 揭示后 ──                            │
│  参考答案要点(要点列表)                  │
│  追问 · 面试官可能接着问                  │

│  [我想好了,看答案 ␣]        ← 揭示前      │
│  [不会 1] [模糊 2] [掌握 3] ← 揭示后      │
│  [问 AI](次要)                          │
└──────────────────────────────────────────┘
```

**交互详述**

1. **进入会话**:入口 = 今天两个主按钮 / ⌘K 动作 / 学习界面空态 / 题库详情「学习此题」/「再过一遍」。队列规则(ADR-0001):**复习会话 = 今天到期题,全量、不设上限**;**学习会话 = 待学习题,按「每次学习题量」截断**(截断时界面注明「共 M 题,本轮先取 N 题」);「再过一遍」= 全部题按题号、不设上限;单题直练 = 仅该题。**⌘K 的「开始复习 N 题 / 开始学习 N 题」与今天页两按钮同名同义**(同队列规则,消除一词两义);「待复习优先、待学习补位」是今天页计划的排序原则,不构成额外的会话类型。**所有会话类型的评分走同一通道、一律写入 SM-2 排期**(ADR-0005)。
2. **揭示前**:唯一主按钮「我想好了,看答案」(␣ / Enter);此阶段可展开代码草稿纸写思路、可点问 AI——写代码属于思考过程,应在看答案之前可用。
3. **揭示后**:展示答案要点与追问;评分三按钮出现(1/2/3 或点击)。
4. **评分**:按下 → 按钮呈现选中反馈 → **当前题卡就地**把按钮组替换为结果条(如「已掌握 · 7 天后再学」「模糊 · 3 天后再学」「不会 · 明天 · 本轮末尾再练一次」),停留约 1 秒后淡出并自动进入下一题——反馈始终归属于产生它的题,不用全局通知(§7-D26);自动推进后焦点回到题卡默认位置,空格/Enter 不会误触上一题的任何按钮。**文案中的天数由 ADR-0002 的固定映射计算得出,是结果不是承诺**;「模糊」的间隔缩短、连续「掌握」的间隔增长均由该映射决定。
5. **「不会」重排**:本题复制一份排到队列末尾,重练时题卡带「重练」标识;**重练的评分覆盖第一次评分(以最后一次为准,§7-D17)**——重练的意义就是当场纠偏,纠偏结果应生效;若重练仍评「不会」,不再二次重排(只重练一次)。
6. **中途退出**:「退出学习」= **结束当前会话**(队列清除,回到今天),不弹确认——已评分的已生效,未评分的只是本轮不学,没有数据损失(§7-D16);这与「切换界面保留会话」(交互 7)是两个语义,给用户一个明确的放弃出口。
7. **会话保持**(产品决策,§7-D3、D16):会话进行中**切换到其他界面**再回到学习,队列与进度原样保留;会话在三种情况下结束——本轮完成(小结)、「退出学习」、或主动开新会话;**小结完成后再次进入学习界面显示空态,不显示旧小结**。
8. **小结**:统计行(学习了 N 道题,掌握 N 道,偏弱 N 道已排进明天)+ 逐题列表(评分 · 题干 · 下次复习时间)+ 操作「回到今天」「再过一遍」。
9. **专注模式**(F):侧栏与状态栏隐藏、题面字号增大、界面其余文字隐去;右下浮出「退出专注 Esc」;Esc 退出。
10. **代码草稿纸**:默认收起,一键展开;编辑内容按题保存(切题自动保存,回来还在);「运行」执行 JS,输出区显示结果;超时(约 3 秒)强制终止并提示;可清空输出;**草稿纸聚焦期间,空格/数字/F 等按键全部作为文字输入,不触发学习快捷键**(§2.4.1 豁免规则)。
11. **问 AI**:打开独立子窗口加载 AI 聊天网页;再次点击聚焦已有窗口;登录一次后续免登。该窗口不获得任何应用权限,题目内容不自动发送(用户自行粘贴,§7-D13)。
12. **笔记**:学习中可展开笔记区书写,按题保存,即时生效。

**状态与边界**:**无进行中会话**进入学习界面(含小结后再进入)显示空态卡——「今天要学什么?」+ 三个入口(开始复习 N 题(>0 时)/ 开始学习 N 题(>0 时)/ 再过一遍)+ 一句说明(先取待复习,再取待学习);从其他入口开队列为空时提示并引导;单题会话的小结按 1 题展示;最后一张卡评完直接进小结。**题目消失**(ADR-0004):队列是开始时的快照,轮到某题时若它已被删除(我的题)或被同步下架(官方题),在该位置显示一条说明(「该题已删除/已下架」)并跳过,小结不计入,进度不回退。

**验收**:全程可只用键盘完成(␣/1/2/3);复习会话含全部到期题、不受题量上限截断;「不会」的题在本轮末尾再次出现且仅一次;重练后的下次复习时间以重练评分为准;小结逐行评分与实际操作一致;评分反馈显示在当前题卡上、换题后不残留;会话切界面再回进度不丢,「退出学习」后再进为空态;草稿纸内容切题往返不丢,**草稿纸内敲空格/1/2/3/F 是正常输入**;队列中已删除/下架的题显示说明并跳过;专注模式期间侧栏/状态栏不可见,Esc 恢复。

### M5 添加题目

**定位**:统一的出题入口——三种来源一条管线,产物去向清晰。

**能力清单**

| 能力 | 说明 | 功能 | 优先级 |
|---|---|---|---|
| 手动写题 | 表单直接写题,人写即人审,保存直接进我的题库;校验(题干非空、答案 ≥50 字、难度合法) | D1 | P0 |
| AI 生成 | 输入知识点,数量由 AI 按知识点广度决定(上限 12);生成过程内置质量规则与自动修正;产物先进待审核 | D2 | P0 |
| 按 JD 生成 | 选一个 JD,可勾选结合简历生成深挖题;产物先进待审核 | D3 | P0 |
| 来源标注 | 手动/AI/JD 落库标注,列表与详情显示来源徽标 | D5 | P1 |

**布局**(单页三段平铺,§7-D7)

```
添加题目 · 手动写的直接进我的题库;AI 与按 JD 生成的先进待审核
┌ 手动写题 ──────────────┐ ┌ AI 生成 ──────────────────┐
│ 题干*                   │ │ 知识点*                    │
│ 考察方向*               │ │ [生成题目] → 生成中…        │
│ 难度(初/中/高)          │ │ → 已生成 N 题 [去审核]      │
│ 模块(选择/新建)          │ ├ 按 JD 生成 ────────────────┤
│ 答案要点*(每行一条,     │ │ ( ) JD 卡片列表,单选        │
│   合计 ≥50 字)          │ │ ☑ 结合简历,生成深挖题       │
│ [保存到我的题库]         │ │ [按 JD 生成题目]            │
└────────────────────────┘ └────────────────────────────┘
```

**交互详述**

1. **手动写题**:必填校验失败在字段下方就地提示,不弹窗;保存成功 → 题直接进我的题库并出现在题库列表,**表单清空但停留在本页**(便于连续录题,§7-D22),toast「已保存到我的题库」。
2. **AI 生成**:输入知识点后点「生成题目」→ 按钮转加载态(可取消,取消则丢弃本批)→ 完成后内联显示「已生成 N 题」+「去审核」直达;生成失败显示错误与「重试」。数量说明文案:「数量由 AI 按知识点广度判断,最多 12 题」。
3. **按 JD 生成**:JD 单选卡片来自 JD 管理;未创建任何 JD 时该段显示引导「先去创建一个 JD」;勾选「结合简历,生成深挖题」(简历为空时该项禁用并提示先去写简历);提交流程同 AI 生成。
4. **深链**:从 JD 详情「按 JD 生成题目」进入时,自动定位到按 JD 段、预选该 JD。
5. **AI 未配置前置引导**(§7-D18):AI 服务未配置(无可用 Key)时,AI 生成与按 JD 两段在输入区上方显示引导条「尚未配置 AI 服务」+「去设置」(直达设置),生成按钮禁用;生成失败的错误提示同样提供「去设置」与「重试」。

**状态与边界**:AI/JD 生成的题一律不直接可见于题库,只在待审核出现;同一段内连续生成多次,各批独立进入待审核。

**验收**:手动保存后我的题库 +1 且来源=手动;AI 与按 JD 生成后待审核 +N;必填缺失时保存被拦且提示位置正确;深链预选正确;生成失败不产生待审核条目;**AI 未配置时生成入口禁用且引导可见,配置后自动恢复**。

**交互详述**

**状态与边界**:全部处理完显示「没有待审核的题」+「去添加题目」。

**验收**:通过后 我的题库+1、待审核-1、状态=待学习;拒绝必经确认且不可恢复;编辑后通过的题以编辑后内容入库;处理完最后一条自动选中消失、空态出现。

**验收**:新增保存后列表置顶出现;编辑中途离开触发守卫、放弃后内容恢复;删除确认后列表与统计消失;深链后出题页该 JD 已预选。

### M8 简历

**定位**:一份随时可被「按 JD 出深挖题」引用的简历底稿。

**能力清单**

| 能力 | 说明 | 功能 | 优先级 |
|---|---|---|---|
| 简历编辑 | markdown 文本编辑,实时显示字数,标注只存本机;离开时有未保存确认,放弃则恢复到已保存的内容 | E3 | P0 |

**布局**(编辑型单栏)

```
简历管理 · 按 JD 生成深挖题会用到它
┌ 我的简历 │ 1,842 字(· 未保存) │ [只存本机] │ [保存 ⌘S] ┐
│ ┌────────────────────────────────────────────┐ │
│ │ 文本编辑区(等宽字体,大面积)                │ │
│ └────────────────────────────────────────────┘ │
└────────────────────────────────────────────────┘
```

**交互详述**

1. **编辑与保存**:输入即统计字数并标注「未保存」,保存按钮可用;⌘S 或点击保存 → toast「简历已保存(只存本机)」,标注消失、按钮回到禁用。
2. **守卫**:有未保存修改时离开,选择继续编辑 / 放弃(放弃 = 恢复已保存内容)。
3. 纯文本粘贴编辑,不做文件导入与格式解析(保持底稿定位,深度加工属规划项 H1)。

**验收**:字数实时;无修改时保存禁用;守卫放弃后内容回到已保存版本;按 JD 生成深挖题的可用性与简历非空状态一致。

### M9 设置

**定位**:配置中心——AI 服务、学习偏好、外观、题库与数据。

**能力清单**

| 能力 | 说明 | 功能 | 优先级 |
|---|---|---|---|
| AI 服务 | 服务商(智谱/DeepSeek/Ollama,OpenAI 兼容);API Key 自填,仅存本机 | G2 | P0 |
| 学习偏好 | 每次学习题量(20 / 50 / 全部)——只决定一轮带多少待学习补位,复习不设上限 | G4 | P1 |
| 外观 | 浅色纸面 / 夜读 | F6 | P1 |
| 官方题库同步 | 显示上次同步时间;手动立即同步;结果反馈(已是最新 / 更新 N 题 / 失败可重试) | C1 | P0 |
| 备份 | 应用内导出进度/笔记/我的题为本地文件(支持 YAML);导入用于恢复 | G3 | **导出 P0** / 导入 P1(§7-D28:本地唯一副本,导出必须先行) |

**布局**(编辑型,分组卡片:AI 服务 / 学习偏好 / 题库与数据 / 关于)

**交互详述**

1. **AI 服务**:服务商三选一;API Key 输入(已保存时显示掩码态),「保存」后显示已保存;「测试连接」验证配置并反馈结果(§7-D10)。
2. **每次学习题量**:20 / 50 / 全部 三选,只决定一轮会话带多少**待学习**补位(ADR-0001);复习会话永远全量。
3. **外观**:切换即时生效并记忆。
4. **同步**:点击「立即同步」→ 加载态 → 完成更新时间与结果;失败显示错误与重试。远端下架的题连带清理其进度/笔记/草稿,题号作废不复用(落库规则见 M10)。
5. **备份**:「导出备份」生成文件;「导入」选择文件后走确认——正文明确警示「将覆盖本机当前全部数据,**包括比备份更新的内容**」,确认后整体恢复。

**验收**:Key 保存后显示已保存态,不再次明文显示;测试连接有成功/失败反馈;同步完成后时间与计数更新;导出文件可再导入恢复;导入前必有确认。

### M10 数据与安全(底座)

**定位**:支撑全部模块的本机数据层——用户可无感,但约束必须被产品尊重。

**能力清单**

| 能力 | 说明 | 功能 | 优先级 |
|---|---|---|---|
| 本地优先存储 | 本机数据库存:学习进度 / 笔记 / 代码草稿 / 我的题 / JD / 简历 / API Key;零上传、无账号、无服务端 | G1 | P0 |
| 官方题库数据 | 首次启动写入内置官方题库;此后自动 + 手动同步远端;远端下架的题连带清进度/笔记/草稿,题号作废不复用;官方题只读 | C1 | P0 |

**产品层约束**(对界面设计的硬性影响):

1. 一切功能的默认假设是离线可用:学习、浏览、编辑、审核不依赖网络;仅 AI 生成、题库同步需要网络,失败可重试且不影响其他功能。
2. API Key 只在本机使用与保存;界面任何位置不得展示完整 Key。
3. 官方题在本产品内不可原地修改或删除(保护与来源库的一致性);「改」的语义 = 复制副本后改。
4. 删除任何题目时,其进度、笔记、代码草稿必须一并清理(确认弹窗文案需如实写明)。

**验收**:断网状态可完整走通学习/浏览/编辑/审核流程;Key 永不明文回显;官方题无任何原地修改入口;同步下架后相关进度与草稿消失且题号不复活。

## 6. 分期建议

以功能文档优先级为准,模块分期取其内最高优先级条目:

- **P0**:M1(框架/导航/⌘K/守卫确认/状态栏)、M2 今天(计划)、M3 学习(会话/评分/重排/小结/追问)、M4 题库(双库/浏览/详情/保护)、M5 添加题目、M6 审核、M7 JD 管理、M8 简历、M9 设置(AI 服务/同步/**导出备份**)、M10 数据底座。P0 = 完整可用的产品,不再收敛(§7-D29);建议实现顺序:学习回路 → 添加题目与审核 → 题库 → 求职 → 设置细项。
- **P1**:专注模式(系统全屏联动)、代码草稿纸、问 AI 子窗口、按题笔记、⌘K 题目直搜、复习预测、按 JD 统计、累计与连续、夜读主题、每次题量偏好、导入恢复、测试连接。
- **P2**:最近学习记录。
- **规划(本期不做)**:H1 简历生成/优化、H2 JD 匹配度、H3 模拟面试、H4 简历多版本。

功能文档未明说、由本文档决策的事项(可推翻,推翻时更新本表):

| # | 决策 | 理由 |
|---|---|---|
| D1 | 三种布局范式:流程型(今天/学习)/ 管理型双栏(题库/审核/JD)/ 编辑型(简历/设置) | 与任务性质匹配:推进式内容要聚焦,管理式内容要密度与就地操作 |
| D2 | 八界面 = 今天/学习/题库/待审核/JD 管理/简历管理/添加题目/设置,⌘1–⌘8 按此序;「添加题目」常驻侧栏底部 | 学习类高频在前;出题是跨场景动作,常驻入口降低发现成本 |
| D3 | 学习会话切走保留、回来自动继续 | 一轮学习是连续体;评分即时落库,无未保存风险 |
| D4 | 连续学习天数:当日完成 ≥1 次评分即计入;中断一天归零重计 | 规则简单可自查;与「学了 N 道题」口径一致 |

| D6 | 来源取值:官方 / 官方复制 / 手动 / AI / JD(官方复制为独立值) | 比「复制归手动」信息更真实,筛选与统计更准 |
| D7 | 出题 = 单页三段平铺(手动/AI/按 JD),不用向导或页签 | 三来源互不干扰、可对照;自用工具无需引导式分步 |
| D8 | 审核详情支持先编辑再通过 | 小错就地修,优于拒绝后重新生成的成本 |
| D9 | 审核不提供批量通过/拒绝 | 逐题阅读即学习,批量会架空质量闸 |
| D10 | AI 服务提供「测试连接」 | 生成前可验证配置,失败可归因 |
| D11 | 评分为唯一写进度的动作;「退出学习」无确认 | 减少打断;无数据丢失风险 |
| D12 | 导入备份 = 整体覆盖恢复,必经确认 | 备份语义简单明确;覆盖不可逆故加确认 |
| D13 | 问 AI 仅打开窗口,不自动发送题面 | 子窗口不授予应用权限(安全模型),且用户应自控发送内容 |
| D14 | 按键豁免范围 = 一切可编辑区域(含代码编辑器等富编辑组件),编辑器内 Esc 优先自身浮层 | 修复评审发现的核心冲突:草稿纸里敲空格/数字/F 原会触发揭示/评分/专注 |

| D17 | 「不会」重练的评分覆盖第一次(以最后一次为准) | 重练即当场纠偏,纠偏结果应生效;自用工具信任用户判断 |
| D18 | AI 未配置时出题页前置引导(引导条 + 按钮禁用 + 失败提示带「去设置」) | 配置问题不应等到生成失败才暴露 |
