# 求职中枢一期(多 JD 管理 + JD 生题迁移)提案

- **日期**:2026-08-31
- **性质**:带选项的方案提案(审计批次 3,`2026-08-28-desktop-ux-ui-audit.md` §4.2 / §5)。
- **状态**:✅ 已确认并实施(2026-08-31,推荐组合 1A/2A/3A;简历多版本只留注释性占位——不加死 schema,二期建表成本相同)。施工记录见 `plans/2026-08-28-ux-audit-fixes.md`。
- **背景**:用户 2026-08-28 指示——JD 定向生题不该是生题页的一个模式,应是求职档案上的动作;求职目标升级为**求职中枢**:多 JD 管理、简历多版本(数据占位)、简历优化 / JD 匹配度分析(阶段 3 立项,不在一期)。这实质是把 ADR-4「档案作为中枢」做实。

---

## 决策点 1:多 JD 的数据模型

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. jds 表(推荐)** | 新表 `jds(id, title, company, content, created_at, last_active_at)`,迁移:现有 `profile.jd/company` 拆成首条 JD;`profile` 表删 jd 字段、留 company/resume | 多 JD 真实体化;JD 匹配度分析(阶段 3)有挂靠点;SQL 可索引可排序 | 需要 migration(006);JD 定向生题调用点要改签名(profile → jd 对象) |
| B. profile.jd 存 JSON 数组 | 不加表,`profile` 里塞 `[{title, content}]` | 无 migration | 结构藏在大字段里,无法按 JD 查询/扩展元数据;与"中枢一等公民"定位相悖 |
| C. 保持单 JD 不动 | 只改 UI 入口 | 零成本 | 不满足"多 JD 管理"的用户指示;阶段 3(匹配度按 JD)还得返工 |

**推荐 A**。迁移脚本把存量 JD 平移为首条(标题取公司名或"JD 1"),无数据丢失路径。

## 决策点 2:路由与页面组织

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. /profile 原地升级(推荐)** | 路由不变;侧栏「求职目标」→「求职中枢」;页内 Tabs:JD 管理(默认)/ 我的简历 / 公司偏好。JD 行内动作:「定向生题」(深链 `/generate?jd=<id>`,AI tab 预选 JD 模式并锁定上下文) | 不动路由表;深链/书签不破;改造集中在单页 | 页面变大,需要 Tabs 分区消化 |
| B. 新路由 /job-hub | 新页面,`/profile` 重定向 | 命名语义新 | HashRouter 自用场景无迁移收益;返回条/侧栏 active 逻辑要跟着动 |

**推荐 A**:自用应用,URL 稳定性 > 命名新鲜感;"中枢"是信息架构升级不是换地址。

## 决策点 3:JD 定向生题的入口迁移

| 选项 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. JD 行内动作 + 深链(推荐)** | 生题页 AI tab 撤「JD 定向」模式按钮;从 JD 条目的 ghost 图标按钮(Sparkles/Target)发起 → `/generate?jd=<id>`;生题页读参锁定「JD 定向 · {title}」上下文,显示返回中枢入口 | 审计指示的原文路径;生题页模式开关消失后更简单 | 生题页需要处理无 jd 参数时的引导(JD 入口只在中枢) |
| B. 生题页保留 JD 下拉选择 | 页内 Select 选 JD | 改动小 | 仍是"生题页的一个模式",未完成解耦 |

**推荐 A**。与批次 2 的 `?mode=manual` 深链模式一致,入口收敛原则已经建立。

## 一期范围与不做

**做**:决策点 1A + 2A + 3A;JD 增删改 + 最近使用排序;简历多版本的**数据模型占位**(resumes 表或 profile.resume_versions,一期仍单版本编辑,多版本切换 UI 留二期)。
**不做**:简历优化、JD 匹配度分析(阶段 3 单独立项);模拟面试(阶段 5)。

## 待用户确认后的施工顺序

1. migration 006(jds 表 + 存量平移)+ storage/profile 层改造(单测)
2. 中枢页重组(Tabs + JD 管理 + 行内动作)
3. 生题页 JD 模式迁移(深链 + 锁定上下文,e2e 更新)
4. 审计文档与 ADR-4 状态同步
