# 品牌与命名规范(CommitCareer)

- **日期**:2026-08-31;**2026-09-02 IA 重构修订**(见文末)
- **性质**:用户指示的菜单/页面标题/App 名与图标重设计,决策经确认(产品名 CommitCareer、橙色闪电图标、菜单重排+改名)。

## 决策

### 产品名:CommitCareer

四处统一:窗口标题(tauri.conf `windows[0].title`)、productName、侧栏品牌、动态 `document.title`(跟随路由 `页面 · CommitCareer`,实现于 app-shell)。bundle identifier `com.resume-assistant.desktop` 不变(日志路径/数据目录不受影响)。

### App 图标

深色圆角方块(`.dark --background` token 色)+ 品牌橙闪电(`--primary` 系),发丝描边呼应深色边框层级。源稿 `/tmp` 一次性生成,产物为 `src-tauri/icons/` 全套(tauri icon 从 1024 PNG 生成);如需改版:改 SVG 源 → playwright 渲染 1024 → `npx tauri icon`。

### 侧栏信息架构(顺序 = 频率 × 工作流)

```
品牌 CommitCareer
总览
【刷题】  官方分类… / 我的题库      ← 高频入口提前
【求职】  求职中枢 → 出题 → 待审核  ← 生成工作流顺序
(底部)设置
```

## 2026-09-02 IA 重构修订(用户指示:功能 = 题库 + 求职两大块)

上表的「生题/草稿区/出题」相关条目作废,以本节为准:

- **功能模型**:题库(官方分类 ×2 + 我的题库)+ 求职(JD 管理 + 简历管理)。
- **菜单**:总览 →【题库】官方分类 + 我的题库(待审数 badge)→【求职】JD 管理 / 简历管理(同一中枢页 `?tab=` 预选)→ 设置。**出题、待审核不再是菜单**。
- **出题 = 各页面按钮 + 弹窗**(独立页 /generate 已删):「添加题目」(手动,直接 approved,来源 manual)、「AI 生成题目」(知识点,进待审核,来源 ai)、「按 JD 生成题目」(JD 行内,进待审核,来源 jd)。来源落 questions.source 列(迁移 007),题目列表显示徽标。
- **题库分类页**:标题就是分类名(无后缀);「开始复习 N 题 / 学习新题 N 题」双入口用户自选(`quiz?focus=due|new`),不再系统替选;各自「是哪些题」深链 `browse?status=`;全清态「再过一遍」(`quiz?force=all`)。
- **总览**:数字行(待复习/新题/待审核)+【题库】分类网格;砍掉行动卡与快捷操作行。(2026-09-02 总览瘦身两轮:无页面副标题;数字行可点规则统一为「仅待审核>0 是链接」;求职区先压缩为一张紧凑卡,同日用户指示整体删除——总览只服务刷题,求职导航归侧栏,状态展示待阶段 3 再评估。)
- **命名**:草稿区 → 待审核(菜单层;ADR-10 术语不变)、题目浏览 → 题目列表、`{分类名} · 刷题队列` 后缀取消。
- AI 产物仍必经待审核(2026-09-02 用户确认保留 ADR-10);`/drafts` 路由保留(总览数字行「待审核>0」+ 我的题库 badge 可达,生成提交后跳转)。
