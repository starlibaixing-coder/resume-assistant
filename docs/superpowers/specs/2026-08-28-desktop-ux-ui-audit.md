## 3. 视觉问题清单(第二轮,专查"看得见"的)

### 3.1 字体系统性破相(本轮最重要发现,实锤)

`index.css:113` `--font-mono: "JetBrains Mono","SF Mono","Cascadia Code","Fira Code",Consolas,monospace`——实测五个字体本机全未命中,且无 CJK 覆盖。后果两层:

- **全站 30+ 处 font-mono 中文渲染成宋体**:所有表单 label(题干/难度/公司岗位/职位描述/我的简历/标签)、返回条"回到xx题库"(`app-shell.tsx:152`)、刷题元信息行(`quiz.tsx:78`)、草稿批次标题、浏览页"模块 08"、侧栏"题库分类"、"+ AI 生题"、"自动保存""输出"、答案面板小标题。深浅模式都中招,浅色更刺眼。
- **数字掉进 Courier(打字机风格)**:队列大数字"135"、进度"1 / 50"、各处计数。

**修法**:`--font-mono` 改为 `ui-monospace, "SF Mono", …, "PingFang SC", monospace`(一行 CSS 修大半);彻底做法是约定 font-mono 只用于代码/ID/纯数字,中文 label 一律 sans。
**取证过程**:getComputedStyle 确认栈 → Range 量宽证明副标题实际是 PingFang(66.91 ≈ 67.12,排除 Songti 60.84)→ 普通说明文字无恙,问题收敛到 font-mono 系。

## 4. 产品方向调整(用户 2026-08-28 指示,四点)

> 以下是指示原文的理解展开,**已确认理解方向,实施前部分需再出细案**(见 §5 批次)。

1. **刷题宽度太窄**:quiz 三处 `max-w-2xl`(672px,`quiz.tsx:77/209/231`),沉浸只藏 chrome 不改宽度,"沉浸"没兑现空间承诺;代码题尤挤。→ 非沉浸加到 max-w-3xl,沉浸 max-w-4xl~5xl;与 #4 配套(卡片变轻后加宽不致行过长)。
2. **生题与简历解耦**:JD 定向生题不该是生题页的一个模式,应是求职档案的附加功能。求职目标升级为**求职中枢**:多 JD 管理(jds 表)、简历多版本、简历优化、JD 匹配度分析;JD 定向生题降级为某条 JD 上的动作(中枢→生题带上下文深链)。这实质是把 ADR-4"中枢"做实,并为阶段 3 定调。
3. **生题 tab 合并 AI + 手动**:侧栏「AI 生题」→「生题」,页内顶层切换;手动加题用页面级表单(现在塞在 max-w-lg 弹窗);4 处散落入口收敛为"去生题"深链。
4. **代码/笔记容器形态**:代码草稿纸 → 大弹窗(上半看题/下半 CodeMirror+输出);笔记 → 右侧抽屉(Sheet);卡片上只留 ghost 图标入口。同时消掉编辑器太小/无收起/emoji 图标/破坏卡片节奏四类问题;Esc 层级需重排(弹窗 > 沉浸退出)。

### 融合优化清单(四点指示 + 两轮审查合并)

**A. 信息架构重组**
- A1 求职目标 → 求职中枢:多 JD 数据模型(jds 表)、简历多版本、页面重组
- A2 JD 生题入口迁移:生题页撤 JD 模式,从 JD 条目发起
- A3 简历优化 / JD 匹配度(本质是阶段 3,单独立项)
- A4 生题页合一(AI/手动顶层切换,手动用页面级表单)
- A5 手动加题入口收敛为 `/generate?mode=manual` 深链

**B. 刷题工作台**
- B1 宽度分级(非沉浸 3xl / 沉浸 4xl~5xl)
- B2 键盘流(空格/回车翻答案,1/2/3 评分,自动聚焦)
- B3 评分条 sticky 底部(治长答案推出视口)
- B4 跳过本题 + 撤销上一题评分
- B5 代码草稿纸大弹窗(题上码下 + 运行输出)

**C. 反馈与信任**:C1 反馈通道统一(toast 为主,补齐草稿审核/编辑保存/保存失败);C2 拒绝=删除加确认;C3 页面级失败加重试;C4 首页 loading 分支;C5 LLM 生成进度+可取消+锁定输入。
