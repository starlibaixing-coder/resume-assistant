## 第一步:产品理解摘要

1. **一句话定义**:本地优先的求职备考工作台——SM-2 间隔重复刷题 + AI 出题(人工审核入库)+ 求职物料(JD/简历)管理,服务前端工程师(含转 AI Agent 方向)的日常备考。
2. **核心目标**:让"每天学什么、何时复习、和目标岗位差多少"成为一个低摩擦、可持续、库不被污染的循环。
3. **目标用户**:求职中的前端工程师;自用为主,顺带分享(分享走冻结的 web 快照)。
4. **核心角色**:单一角色(考生本人),无权限/多租户;无登录体系。
5. **核心任务**:① 每日学习循环(复习到期题 + 学新题,三档评分);② 出题(手动 / AI 按知识点 / 按 JD);③ 审核AI 产物(通过/拒绝);④ 维护 JD 与简历;⑤ 管理我的题库(编辑/删除/官方题复制)。
6. **核心对象**:题库分类(官方 fe/agent + 我的题库)、模块、题目(难度/focus/答案要点/追问)、学习卡(SM-2 状态:待学习/待复习/已掌握)、评分(不会/模糊/掌握)、待审题(pending)、笔记、代码草稿、JD、简历档案、LLM 配置。
7. **关键业务流程**:学习循环(队列→答题→评分→调度反馈→完成态);出题审核流(生成→预览→待审核→通过入队/拒绝删除);求职物料流(JD/简历→按 JD 生成)。
8. **术语与缩写**:待学习(unseen)/待复习(due)/待审核(pending)/学习队列(queue)/已掌握(mastered)/官方题库/我的题库/焦点(focus)/追问(followups)。**禁止上 UI**:草稿区、生题、新题、刷题(动词)、待确认等(见术语表)。
9. **高频功能**:学习页(quiz)、总览、分类页——每天多次。
10. **低频但重要**:添加题目、待审核、JD/简历管理、设置(含数据清空/官方库同步)、题目列表管理。
11. **文档不足处(已按合理假设处理)**:① 无多题库/多用户规划——按单用户单机设计;② 简历多版本、简历优化、JD 匹配度为路线图阶段 3,本期不做,IA 预留;③ 学习数据统计(热力图/正确率曲线)无需求方,本期不做,总览"最近动态"已覆盖最低需求。

## 第四步:信息架构

### 全局导航(侧栏,官方 shadcn Sidebar,collapsible="icon")

```
Sidebar
├─ 总览 /                          ← 工作台
├─ 【题库】
│  ├─ 前端工程师 /fe               ← 官方分类,右侧灰字题数
│  ├─ AI Agent 工程师 /agent
│  └─ 我的题库 /my                 ← 灰字题数 + 待审 badge
├─ 【求职】
│  ├─ JD 管理 /profile
│  └─ 简历管理 /profile?tab=resume
└─ (底部) 设置 /settings
```

### 页面层级

```
/ 总览(工作台)
/:category 分类页 ─┬─ /:category/quiz   学习页(沉浸可切换)
                   └─ /:category/browse 题目列表
/add      添加题目(手动/AI/按JD 三段平铺)
/drafts   待审核(无菜单,指标与 badge 可达)
/profile  求职中枢(JD/简历 tab,?tab= 深链)
/settings 设置
```

### 布局形式

**左侧 Sidebar + 内容区**(无顶部 Header)。页面内用 PageHeader 承载"我在哪+能做什么+主操作"。
混合使用:总览=工作台卡片;分类页=统计+行动卡;学习页=专注单列;列表页=筛选+行列表;添加题目=分段长表单;审核=收件箱式批处理。深链保持 `?focus= ?status= ?m= ?jd= ?tab=`。

### 为什么适合

单用户本地工具、核心是每日循环:侧栏保证"学习/出题/审核/物料"四类目标一键可达且不占内容宽度;无 Header 减少垂直空间消耗(学习页收益最大);工作台总览承接"今天该干嘛"的调度决策;扁平两级路由让层级感弱、深链多,面包屑只需覆盖"分类→子页"一层。

## 第五步:核心用户流程

### P0 首次使用(含 LLM 配置引导)

- **目标**:从安装到开始学习/AI 出题 ≤3 步。
- **起点**:`/` 总览。
- **步骤**:① 总览看到分类卡(未开始)→ 点分类 → ② 分类页"开始学习 N 题"直接学(无需配置);或点「添加题目」→ AI 生成 → ③ 检测未配 LLM → Alert 引导"去设置" → ④ 设置页填 baseURL/model/key → 「测试连接」→「保存 LLM 配置」→ 返回。
- **每步信息/操作/反馈**:总览=分类+指标;生成表单前置 Alert(未配置 LLM+链接);设置保存 toast"LLM 配置已保存"+测试结果就近显示。
- **可能出错**:key 错(测试连接失败,错误含 provider 返回信息);浏览器预览 key 不持久(说明文案已写明)。
- **更短路径**:AI 生成表单内联 Alert 直达设置,不经菜单找。
- **删/合/延/自动**:无账号体系可删;主题等设置延后到有需要时。

### P1 每日学习循环(最高频)

- **目标**:清空今日待复习 + 学新题。
- **起点**:总览(待复习 N 指标/快捷入口"开始复习")或分类页。
- **步骤**:① 进入 quiz → ② 看题(强制先想:按钮"我想好了,看答案")→ ③ 对照答案要点/追问 → ④ 三档评分(不会/模糊/掌握,快捷键 1/2/3,可见 kbd 提示)→ ⑤ 调度反馈("明天再来")→ ⑥ 循环至完成态(本轮学了 N 道,掌握 M 道)→ ⑦ 继续下一轮 / 回分类 / 浏览题目。
- **反馈**:进度条+N/M 计数;评分后按钮推进+反馈文案;撤销上一题随时可点。
- **可能出错**:误评分(撤销救回,含首评删行);长答案(吸底评分条保证可达);跳过不污染调度。
- **更短路径**:总览"开始复习 N"一键带 `?focus=due` 深链进会话。
- **删/合/延/自动**:队列计算自动;进度自动落库无保存动作。

### P2 出题(创建流,分步)

- **目标**:把知识点/JD 变成入库的题。
- **起点**:任意页「添加题目」/ JD 行内 Sparkles 深链 `/add?jd=`。
- **步骤**:① /add 选段落(手动=表单直接保存;AI=知识点+难度→「生成题目」;按JD=选 JD→生成)→ ② 生成中(计时+可取消,输入锁定)→ ③ 预览列表(逐题展开看质量)→ ④ 「提交审核(N 题)」→ 跳 /drafts;手动则「保存题目」直接入我的题库。
- **反馈**:生成结果"N 道题·自修正 X 次";提交 toast+跳转。
- **可能出错**:未配 LLM(前置 Alert);生成失败(错误 Alert+可重试);知识点为空(就近校验)。
- **删/合/延/自动**:预检自修正自动;难度默认"不限"减少决策。

### P3 审核(高风险批处理)

- **目标**:快速过完 pending,库保持干净。
- **起点**:总览"待审核 N"指标/侧栏 badge → /drafts。
- **步骤**:按批次分组 → 逐题:题干常显,展开看答案要点 → 「通过,进我的题库」/「拒绝」(AlertDialog 确认=永久删除)→ 批次头「本批全部通过」。
- **反馈**:toast(已通过/已拒绝)+行即时消失;失败 toast 带原因。
- **可能出错**:误拒(确认弹窗拦截);批量中途失败(报错并可重试)。
- **删/合/延/自动**:展开才见答案是故意的(先自答再对照,审核即学习)。

### P4 求职物料维护

- **目标**:维护 JD 与简历,供按 JD 生成消费。
- **步骤**:JD=列表+新增/编辑 Dialog+删除 AlertDialog;简历=单表单+dirty 追踪+显式保存;离开未保存→拦截确认。
- **可能出错**:简历未保存切走(拦截);JD 内容为空(就近校验)。

### P5 题库管理

- **目标**:查、改、删、复制题。
- **步骤**:browse 筛选(模块/难度/状态组合)→ 行内:我的题=编辑 Dialog/删除 AlertDialog;官方题=「添加到我的题库」(复制副本,已复制置灰)。
- **反馈**:toast;行状态即时更新。

## 第七步+第八步:核心页面设计规格(含重点页线框)

> 共通状态设计(所有页面引用,不逐页重复):加载=Skeleton 占位(结构同终态);空=EmptyState(图标+标题+一句解释+动作按钮);错误=ErrorState(标题+原因+「重试」);提交中=按钮 loading 文案"保存中…/提交中…"且禁用;成功=toast(或页内状态行,见文案表);无权限/部分失败不适用(单机),LLM 部分失败=生成错误 Alert 保留旧结果。

### 8.1 总览(工作台)`/`

- **目标**:10 秒内回答"现在该干嘛"。
- **信息优先级**:① 待复习/待学习/待审核三指标;② 学习中/未开始分类卡(可一键进入);③ 快捷入口+求职两行;④ 最近动态。
- **布局**:顶部问候区(时段问候+日期+累计学习 | 右侧三指标);下方左主栏(分类卡组+最近动态时间线)、右栏快捷入口单卡(sticky)。
- **主要操作**:主=「开始复习 N」(有待复习时);次=「开始学习 N」「去审核 N」「添加题目」;文字链=JD/简历两行。
- **组件**:Card/CardContent、Progress(渐变进度)、Button(asChild+Link)、Skeleton、SectionHead(共享)。

## 第九步:表单体验规范

1. **原则**:字段最少化(能默认则默认);必填`*`显式标记;一个控件一个语义(多选一=RadioGroup/Select,开关=Switch,短文本=Input,长文本=Textarea);错误就近且给修法;提交按钮表达结果。
2. **组织**:≤7 字段单列平铺(手动加题);≥2 个自然组用分区小节(/add 三段);弹窗表单≤4 字段(JD)。
3. **必填规则**:题干*、答案要点*(≥50 字)、JD 内容*、API key*(测试/生成需要);其余选填。选填在 label 标注"(可空)"。
4. **校验时机**:提交时统一校验;失败滚动到首个错误(同屏时直接就近显示)。
5. **错误规范**:Alert destructive 容器;文案=什么错+怎么修(“答案要点至少 50 字,当前 32 字——再补充些细节”)。
6. **成功规范**:入库类=toast+跳转或行更新;配置类=toast"LLM 配置已保存";自动保存类=页脚常驻"自动保存"弱文本(不打扰)。
7. **取消/草稿/退出**:弹窗表单取消=丢弃(内容短,重填成本低);简历长表单=dirty 拦截(切 tab/离开确认);笔记/代码=自动保存无需处理。
8. **高风险确认规范**:AlertDialog;标题=问句点明对象;正文=范围+级联影响+"不可恢复";取消=outline 左,确认=destructive 右,文案=具体动词(「确认删除」「确认拒绝」「确认清空」)。
9. **字段组件映射**:题干/公司/URL=Input;JD/简历/答案=Textarea(等宽字体仅代码语义处);难度=RadioGroup;模块/JD=Select;生成范围=两个互斥 Button(临时态,提交时才生效,可保留)。
10. **文案模板**:见第十二步文案表。

## 第十二步:文案系统

1. **语气**:专业、直接、平实;对用户用"你";不感叹、不营销、不卖萌。
2. **命名规则**:页面名=名词(总览/待审核/设置);功能名按术语表;数字标签="术语 N"。
3. **页面标题规则**:PageHeader 主标题=页面名;子页=`{分类} · 页面`;不加装饰前缀。
4. **按钮规则**:动词开头+结果对象,含数量(「开始复习 12 题」「提交审核(8 题)」);禁用裸"确定/提交/操作"。
5. **表单标签规则**:名词短语;可空标注"(可空)";单位入标签不入占位。
6. **空状态规则**:一句"是什么/为什么空"+一个动作按钮;不复述按钮文案。
7. **错误提示规则**:什么错+怎么修;保留技术细节于 description/日志。
8. **成功提示规则**:结果+去向("已通过,进我的题库")。
9. **确认弹窗规则**:标题问句;正文=影响范围+级联+"此操作不可恢复"。
10. **Tooltip 规则**:动作名(+快捷键),≤12 字。
11. **权限不足**:不适用(单机)。
12. **加载中**:骨架屏为主;按钮内进行态="动词+中…"(保存中/生成中/同步中)。

**关键文案对照表**(A=本应用采用;B/C 备选风格,不混用):

| 场景 | 原文案 | A 简洁(采用) | B 友好 | C 专业 |
|---|---|---|---|---|
| 手动加题成功 | 已加入我的题库(+id) | 已保存到我的题库 | 这道题已经进你的题库啦 | 题目已写入我的题库 |
| 保存失败 | 保存失败+原因 | 保存失败(原因见下) | 没保存上,再试一次? | 写入失败:{detail} |
| LLM 未配置 | 还没配置 LLM。先去设置页填 API key | 还没配置 AI 服务——先去设置填 API key | 想用 AI 出题,先到设置里配一个 key 吧 | LLM 未初始化:缺少 API 凭据 |
| 网络错误(生成) | 接口报错原文 | 生成失败:{原因} | 网络开小差了,稍后再试 | 请求失败:{status} |
| 无数据(我的库) | 我的题库还没有题+说明 | 同前(合格,保留) | 你的题库还空着 | 暂无记录 |
| 搜索无结果 | 无符合条件的题 | 没有符合筛选的题 | 啥也没筛到 | 0 条匹配结果 |
| 删除确认 | 删除这道题?… | 同前(合格) | 真的要删吗? | 确认删除资源 |
| 表单校验失败 | (裸红字) | Alert:答案要点至少 50 字,当前 32 字 | 还差一点就够 50 字啦 | 校验失败:MIN_LENGTH |
| 退出未保存 | 仅 beforeunload | 确认离开?修改还没保存 | 改动还没保存,确定走吗 | 未保存更改将丢失 |
| 学习完成 | 本轮完成,学了 N 道题 | 同前(合格,保留) | 今天又变强了一点 | 本轮会话结束:N 项 |

清理项:文本箭头"→"、营销句"祝你离 offer 近一步"→ 改为平实的"今天也离目标近一步。"(保留温度、去掉口号感);「添加题目」页返回按钮→back 槽;空态与按钮重复文案合并。
